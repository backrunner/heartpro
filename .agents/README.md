## 已确定的产品原则

1. 首页是「当天概览 + 所有历史 ECG 的连续分页列表」；当天概览进入可左右切换日期的日详情和日／周／月／年趋势；单条波形进入 ECG 详情。
2. 波形采用医院纸质心电图的网格、走速、增益和标尺表达，明确显示来源为 Apple Watch 单导联。详情可以放大并横向浏览整条记录，不能把一条导联画成十二导联。
3. ECG 详情包含完整波形、总览、备忘和模块化分析。0.4 新增早搏候选与节律参考分，可查看逐搏依据并返回原图；总览仍展示 bpm、指标统计、可分析比例与限制。
4. 分析覆盖整条记录；噪声区、无法测量的波段和未完成分析必须显式显示，不能只选取好看的几秒代表全部记录。
5. 按 2026-09-18 后续要求继续研发早搏与评分。0.4.0 开放明确标为候选的早搏特征与可解释的节律参考分，U 波仅在足够重复候选时显示；没有实现的医学分类与固定演示分不展示。
6. 已实现的测量因本次信号质量、边界或适用条件而缺失时，保留原因与空值；不能用零或演示值代替结果。后续新增能力需先完成相应算法与验证，再加入支持列表。
7. Apple Watch 的类似 I 导联心电不能可靠识别或排除心梗、心肌缺血。可以研究可测 ST／T 形态及变化，首版不输出「疑似心梗」「无缺血」或相应风险分。相关用户需求的替代交付见能力边界文档。
8. HealthKit 中的 Watch ECG 是只读的；备忘保存在 HeartPro。用户主动选择的受支持症状可以作为独立症状样本写入健康，不能修改原始 ECG，也不能承诺写回健康 App 的 ECG 备注栏。
9. 默认完全本地分析、无需账号；不上传原始心电、症状或备忘，不启用 CloudKit 健康数据同步。Apple 自身的健康数据同步不等于 HeartPro 获得了任意云存储权限。
10. 固定展示「仅供参考，不能用于医疗用途，不能替代医生诊断」。这句话不能替代算法验证、准确的产品描述和适用地区的产品合规判断。

| 原始需求 | 对应方案 | 发布约束 |

| 日／周／月／年趋势 | 模块设计 §9 | 空缺不补零，跨算法版本不直接连接 |
| 单条总览、bpm、波段统计与范围 | 模块设计 §6、§7 | 分指标置信度；不可测项目显示原因 |
| 规律性异常、异常搏动、早搏候选 | 模块设计 §6 | 分类别验证后开放，不承诺识别所有早搏类型 |
| 潜在心梗／缺血信号 | 能力边界 §2；模块设计 §6.9 | 不交付疾病筛查结论；可复核形态与就医信息替代 |
| HRV、全段离群点 | 模块设计 §6.7、§6.8 | 超短时 HRV 限制、异常节律与伪差剔除规则 |

| 仅供参考、不能用于医学用途 | 各页面文案、能力边界、里程碑发布门槛 | 高分或未提示异常不表示安全 |

## 执行规则

- 按里程碑逐步实现；每个阶段提供可运行演示、检查结果和明确的未验证项。
- 文档中的性能数值、样本数及算法阈值均为规划目标或初始实验配置，不是实测成绩或医学标准。
- 不因赶进度把未验证的实验算法改名为健康建议。未实现的能力从产品界面隐藏；已实现测量因本次记录不可用时保留原因，波形、基础统计、来源分类与备忘照常提供。
- 实施中涉及目标系统、数据模型、指标含义或算法版本的调整，同步更新这组文档及验收依据。
