# HeartPro 实现计划

## 1. 目标与默认决策

构建原生 Swift 应用，从用户授权的 iPhone HealthKit 读取已经同步的全部 Apple Watch ECG，提供纸质心电风格的历史列表、日概览、趋势、完整波形、可复核分析和备忘记录。

| 项目 | 初始决策 | 理由／限制 |
| --- | --- | --- |
| 首发平台 | iPhone，暂以 iOS 18+ 为基线；支持横屏心电详情 | SwiftUI、SwiftData、Swift Charts 及现代并发足够；P0 核对设备覆盖 |
| Swift | Swift 6 语言模式，开启严格并发检查 | 用 actor 隔离查询、存储和计算；具体 Xcode 版本在 P0 固定 |
| Watch App | 首版不要求单独安装 | 读取系统 ECG App 已采集并同步的记录；不自行启动 ECG 测量 |
| UI | SwiftUI + Observation + Canvas；趋势用 Swift Charts | 无 WebView 产品界面；波形渲染与分析解耦 |
| 存储 | SwiftData 元信息／结构化结果 + 本地二进制波形文件 | 避免把大量采样点当作单独数据库对象 |
| 算法 | 原生 Swift + Accelerate；确定性处理管线 | 端侧运行、版本可追踪、无需服务器；Core ML 仅作为后续验证选项 |
| 解释文本 | 基于结构化结果的审定模板 | 不让生成式模型自行编造医学解释或疾病结论 |
| 数据来源 | ECG 必需；系统 HRV、相关症状按需读取 | 不默认索取全部健康类型权限 |
| 隐私 | 离线可用，无账号、无默认遥测、无健康数据云同步 | 数据保护、备份排除、导出和清理路径纳入首版 |
| 人群说明 | 默认沿用 Apple ECG 的适用条件；不面向未满 22 岁人群作解释 | 不为了年龄门槛额外强索出生日期；记录的存在也不表示所有参考值适用 |
| 导出 | 首版安排波形与参考报告 PDF、系统分享 | 必须含来源、单位、比例、分析版本、限制；用户主动触发 |

以上为可实施默认值。P0 若发现系统版本、授权或真实样本特性不符，应记录决策修订，不在产品里隐藏降级。

## 2. 产品范围与交付分层

### 2.1 首个内部可用版本

- 授权引导、最近记录优先显示、全部历史索引与可恢复分析队列。
- 当天概览、历史分页列表、日详情、趋势页面及完整导航。
- 全长 ECG、网格标尺、缩放／横向滚动、Apple 来源分类、平均心率。
- 信号质量、R 峰、RR、基础统计、满足条件的超短时 HRV和离群候选。
- 本地备忘、快速症状、用户确认的症状写回健康。
- 评分结构与实验实现；只有满足验收时才启用公开可见数值。

### 2.2 完整目标版本

在上述基础上完成分波段测量、PR／QRS／QT 与条件化 QTc、代表性心搏与离散分布、规则性异常候选、经分类验证的早搏候选、个人基线与分层趋势。每项都有独立开关与拒答路径。

「识别各类早搏」转为逐类建立证据的能力矩阵；无法区分的事件显示「提前搏动候选，类型无法可靠区分」。心梗／缺血功能按[能力边界](./evidence-and-boundaries.md)提供单导联限制说明和形态复核，不能在完整版本中偷换成疾病筛查。

### 2.3 首版不纳入

十二导联重建、从普通心率样本反推 ECG、全天连续监护、急救分诊、诊断／用药建议、云端分析、社交分享流、医生远程诊疗、自动联系他人。也不把不连续的 30 秒记录拼接成连续监测数据。

## 3. 页面与交互

### 3.1 首页：当天概览 + 历史 ECG 列表

从上到下：

1. 日期和同步状态，例如「今天 · 已同步至 10:32」；同步错误有重试入口。
2. 可点击的当日概览卡：当日心电参考分／暂不可评估、今天记录数、可评估数、bpm 中位数及范围、简短摘要、样本覆盖说明。
3. 分析进度条：例如「历史已索引 386 条，已分析 240 条，12 条无法评估」。不是阻塞全屏弹窗。
4. 按时间倒序、按日分组的连续分页列表；日期分组只负责组织历史，不把列表限制为当天。

每个 ECG 卡片的顺序固定为：时间与时长 → 纸质网格波形预览 → 参考结论 → 单次参考分、bpm、质量和症状／备忘标记。预览为明确标注时间范围的代表性片段，如「0–6 秒预览」，不能将整条 30 秒压到卡片宽度后仍标称标准走速。预览暂不可用时显示真实加载状态。

列表每页初始 30 条，本地游标分页；滚动接近页尾时预取。卡片只加载缩略波形和结果摘要，不在 `body` 中查询 HealthKit 或运行算法。点击卡片或波形进入同一 ECG 详情；返回保留滚动位置。同步新记录时不突然改变用户正在阅读的历史位置。

### 3.2 当日与趋势页面

从首页当日卡片进入，顶部保留「当日 / 趋势」两个 tab：

- 当日：日期标题、左右箭头、横向翻页手势、日历选择、回到今天；下方是当日总览、指标分布、异常候选时间线和当日 ECG 列表。
- 趋势：日／周／月／年分段选择器；可以选择参考分、心率、短记录 HRV、系统 SDNN、可评估记录比例、候选事件比例等指标。
- 当日页面的左右翻页只绑定页级横向手势，不吞掉系统返回手势或列表垂直滚动；日历允许直接跳到很早的历史日期。
- 日趋势展示单次记录；周展示每日聚合；月展示每日聚合；年展示每月聚合，并可点击进入明细。X 轴按真实日期而非等距记录序号排列。
- 空日期显示「当天没有可读取 ECG」，不显示 0 分。少量记录提示「仅反映已记录片段」。图表点选展示样本量、可分析时长、来源和算法版本。

### 3.3 ECG 详情页

页面顺序：

1. 记录时间、导联／设备来源、同步状态和 Apple 原始分类。
2. 完整波形查看器：默认纸速 25 mm/s、增益 10 mm/mV 的标准比例表达；整个记录可横向滚动，支持缩放、横屏、跳到开头／末尾、时间标尺、原始／处理后视图及标记开关。屏幕实际毫米的限制见模块设计 §5。
3. **总览**：在所有分析模块之前，显示参考分、平均／最低／最高可靠心率、记录时长／有效时长、质量与置信等级、各波段统计与参考范围。
4. 质量与可分析区间：按时间着色的质量条、缺口／运动干扰／截断说明。
5. 心率与节律：RR tachogram、心率变化、Apple 分类与本地特征分别呈现。
6. 波段与间隔：P／QRS／T 代表性心搏、PR／QRS／QT／QTc 分布、每项样本数与置信度。
7. 异常搏动候选：时间线、提前搏动／形态偏离／连续模式卡片，点击将波形定位到证据片段。
8. HRV：NN 覆盖、RMSSD、SDNN、Poincaré 图、超短时测量说明。
9. 离群点：全段特征分布、MAD 候选、时间位置、排除噪声后的解释。
10. ST／T 形态与能力说明：默认展示单导联限制；只有独立验证通过后才显示研究性测量，不显示心梗或缺血判定。
11. 备忘：快捷感觉／不适标签、发生时间、严重程度、持续时间、场景、自由文本、写回状态。
12. 方法、版本、参考依据、PDF 导出与固定用途说明。

每个分析模块遵循统一结构：「一行结论 → 指标／图表 → 原始证据入口 → 置信度与限制 → 方法详情」。不可测模块保留标题并解释原因；实验关闭的高级模块用能力说明代替假数据。

### 3.4 状态与可访问性

必须设计：首次使用、HealthKit 不可用、暂无可读记录、未完成 Watch 同步、波形下载中、正在分析、部分成功、质量不足、来源已删除、磁盘不足、应用被中断后恢复、写回授权不足、写回待重试。

支持 Dynamic Type、VoiceOver、深浅色和减少动态效果。波形提供可朗读的摘要与事件列表；不依赖红／绿区分健康状态。分数和异常候选不能仅靠颜色表达。日切换、缩放、游标等手势都有按钮替代。

## 4. 原生模块落地

建议一个 Xcode App 工程加一个本地 Swift Package，先在包内划清 target 边界，不为每个页面建单独仓库。

```text
HeartPro/
  App/                         应用装配、路由、启动与生命周期
  Features/
    Onboarding/                权限与用途说明
    Timeline/                  首页、历史列表
    DailyInsights/             日详情、趋势
    ECGDetail/                 波形与分析模块
    Notes/                     备忘与症状写回
    Settings/                  数据管理、方法与隐私
  Packages/HeartProCore/
    Sources/
      ECGDomain/               值类型、状态、协议、单位
      HealthKitGateway/        系统查询、症状读写
      ECGPersistence/          SwiftData、文件、迁移
      ECGSignalProcessing/     滤波、质量、检测、测量
      ECGAnalysis/             管线、结果与解释模板
      ECGInsights/             评分、日聚合、趋势
      ECGPresentation/         波形坐标、LOD、图表 DTO
    Tests/                     纯算法、集成、迁移与夹具
  HeartProTests/
  HeartProUITests/
  Tools/ECGBenchmark/           Swift 命令行基准与离线评估
  TestFixtures/                合成或许可允许的去标识数据
  .agents/                    本规划、后续验收与决策记录
```

`ECGDomain` 不依赖 UI、HealthKit 或 SwiftData；算法只接收数值与元信息。UI 使用主 actor 的 ViewModel，存储经单独 actor 调用，HealthKit 类型在网关内转换成可跨隔离域传递的值类型。框架对象的 `Sendable` 以 SDK 为准，不用全局 `@unchecked Sendable` 绕过检查。

## 5. 数据读取、历史分析与恢复

### 5.1 权限

- 首次按用途请求 ECG 读取；系统 HRV 和原有症状按用户启用功能时请求。
- 写入症状单独申请，不因为用户允许读取就认定可以写入。
- 配置 `NSHealthShareUsageDescription`、需要写入时的 `NSHealthUpdateUsageDescription`、HealthKit entitlement；后台能力验证后再启用相应 entitlement。
- 授权 API 完成只表示授权流程结束，不意味着所有读取类型被允许。

### 5.2 同步策略

1. 最近记录快速查询，用于首屏；按 UUID 幂等落库。
2. 全历史 anchored query 从空 anchor 起步，分批读取全部可访问元信息；每批保存样本、删除状态、待分析任务及新 anchor，构成同一提交边界。
3. 后台工作队列按「正在查看 → 今天／最近 → 其余历史」加载全长电压、验证单位和完整性、执行分析。为老记录保留队列配额，避免持续新增导致永远处理不到历史。
4. 前台启动、回到前台、手动刷新触发增量；观察更新只用来调度增量，不将通知视为具体样本集合。
5. 系统允许的后台时间仅做可中断批次；锁屏数据保护、低电量、过热、系统撤回执行时间时保存进度后暂停。
6. 删除来源 ECG 时，清理波形、分析、缩略图和聚合缓存；用户自己写的备忘保留为「原 ECG 已删除」的独立笔记，提供单独删除入口。

完成标准是「在最近一次同步边界内可读取的全部样本均已索引，且每条有终态或明确待处理原因」，不是「手表自购买以来所有记录都一定已在手机上」。长历史的剩余工作必须可见，不能用最近 N 条冒充全部历史。

### 5.3 成本控制

元信息批次初始 200 条；波形获取及 CPU 分析并发从 1–2 个任务起，根据实机测量调整。列表不常驻全量波形。以 512 Hz、30 秒、Float32 电压举例，电压数组约 60 KiB；若保存逐点 Float64 时间偏移，未压缩约 180 KiB／条，10,000 条可能接近 1.8 GiB，尚不含索引与缓存。

因此文件格式允许以经过完整性验证的均匀时间轴紧凑编码；必须保留原有异常时间戳和缺口。磁盘预算默认先设 256 MiB 可再生波形／缩略图缓存，最近和打开中的记录优先保留。被逐出原始文件的结果保留 provenance，详情需要时重新从 HealthKit 加载；来源不可用时不能从缩略图恢复假原始波形。永久保存全历史原始文件可作为用户显式选项，展示空间估算。

## 6. 分析开发顺序

1. 首先建立无损读取、质量标记和可重复的波形夹具。
2. 分别建立显示、R 峰检测、形态测量支路，明确滤波对幅值与时序的影响。
3. 验证 R 峰和 RR 后，做基础 bpm、全段统计、超短时 HRV及离群候选。
4. 验证分波段定位后，按可测覆盖输出间隔统计；不把缺失 P 波默认为异常。
5. 在独立标注上逐类评估不规则／提前搏动／形态异常候选，再考虑命名为房早或室早候选。
6. 基于已验证特征建立参考分；评分不使用信号差、年龄未知或缺失波段直接扣分。
7. 日聚合和趋势使用稳定版本的结果集，明确日覆盖、样本偏差和重算状态。

算法细则、公式和数据结构见[模块设计](./module-design.md)。工程测试只能证明程序按规定执行，不能替代算法标注评估和医学解释审核。

## 7. 备忘与健康写回

备忘支持多条记录、发生时间、持续时长、轻／中／重程度、自由文本和多个快捷标签。初始标签：无明显不适、心悸、漏跳感、胸闷／胸痛、气短、头晕、晕厥、疲劳、运动后、咖啡因、压力、睡眠不足。标签不是自动诊断；「无明显不适」与具体不适标签互斥。

默认只在本地保存；启用「同时记录到健康」后，显示可映射的症状与不能写回的上下文标签。写入流程独立于本地保存，以 outbox 追踪进行中、成功、失败、授权不足、更新与删除。编辑已写回条目时采用同一同步标识的更高版本，不产生无数重复样本；删除时明示「只删本地」或「同时删除 HeartPro 写入的症状」。

## 8. 数据保护与用户控制

- 本地数据库、WAL／SHM、波形、缓存和临时导出统一使用受保护目录与文件保护策略；不得只保护主数据库文件。
- 应用自建健康数据存储排除系统云备份；不启用 SwiftData CloudKit 同步。备忘因同样属于健康相关内容也受此规则约束。
- 默认完整数据保护；设备锁定无法读取时停止任务并留待解锁继续，不能为了后台便利静默降级保护。
- 日志仅记录非敏感运行指标与匿名内部任务标识；禁止输出波形、备注、症状、精确时间或 HealthKit UUID 到远程崩溃平台。
- 切后台隐藏敏感界面快照；导出需要用户主动发起，临时文件完成分享后按生命周期清理，并说明导出文件脱离应用后由用户管理。
- 数据管理区提供清理可再生缓存、删除本地备忘、清空全部 HeartPro 数据、重建分析与查看授权说明。清空 HeartPro 不删除 Apple 原始 ECG。
- 用户关闭读取权限的事件无法可靠直接检测；保留已导入数据的事实必须透明，并提供立刻清除本地副本的入口，不能宣称撤销授权会自动删除本地数据。

## 9. 验证方法

| 层级 | 验证内容 | 不能证明什么 |
| --- | --- | --- |
| 单元／属性测试 | 单位、时间轴、统计公式、缺口、阈值边界、确定性和拒答 | 临床准确度 |
| 数据回放评估 | R 峰、边界误差、候选事件敏感度／阳性预测值、拒答率 | 未覆盖人群或新设备表现 |
| HealthKit 真机 | 历史读取、撤权后状态、删除传播、锁屏恢复、症状写回 | 算法医学有效性 |
| UI／可访问性 | 分页、日期切换、手势、标尺、事件定位、文案与导出 | 所有负载性能 |
| 大历史压力 | 10,000 条合成／去标识索引与回放、内存、磁盘、耗电、恢复 | 一万条真实 HealthKit 的系统表现 |
| 医学与产品评审 | 参考区间、解释和用途边界、评分误导风险 | 获得监管许可或诊断资质 |

每次报告区分模拟器、真机、公开数据库、Watch 数据和合成压力测试。详细目标与阶段门槛见[里程碑](./milestones.md)。

## 10. 风险、决策与发布路径

| 风险 | 实施处理 | 未解决时如何交付 |
| --- | --- | --- |
| 单导联 P／T 边界不稳定 | 分指标质量门控；扩大标注样本；保留拒答 | 保留波形与 R／RR，间隔显示不可测 |
| 早搏分类证据不足 | 先做不带疾病命名的候选，逐类独立验证 | 显示变化证据，不输出具体早搏类型 |
| 参考分缺乏可解释性 | 冻结评分目标、预注册公式、验证重测与分组偏差 | 发布基础指标；分数显示暂不可评估 |
| 历史规模超出手机预算 | 流式队列、索引分页、文件 LRU、断点恢复 | 进度透明；继续前台时补齐，不静默截断历史 |
| 背景 ECG 通知不可用 | 启动／回前台／手动刷新增量 | 明示同步时间，不承诺后台实时 |
| 备注无法修改 Apple ECG | 本地关联 + 独立标准症状写回 | 保留完整本地备忘 |
