# 0.5 每日心脏健康与 ECG HRV

2026-09-18 的需求：首次连接一起申请心率、ECG、HRV 读取；日常心率概览和趋势；历史记录性能与日期查找；精简记录卡片；分段参考区间及偏离说明；本次 ECG 的 HRV 聚集图。

## 数据与授权

- `HealthKitGateway.readTypes` 一次请求 `electrocardiogram`、`heartRate`、`heartRateVariabilitySDNN`，不附带症状写入权限。HRV 查询不再单独弹授权。
- 旧版连接状态保留；尚未走新版授权的用户在首页看到补充连接入口。读取授权界面完成不等于各项已获准，HealthKit 不向应用透露读取拒绝状态。
- 首页每日平均心率使用 HealthKit 当天所有可读取心率样本的 `discreteAverage`，范围使用 `discreteMin/Max`；它不由少量 ECG 平均心率代替，也不是静息心率。
- 日视图按小时展示平均值及最低–最高；周/月按日，年按月汇总每日心率均值的中位数。趋势顶部为图中各时段均值或汇总值的中位数，不称为全天连续监测平均值。
- HealthKit HRV 使用原始 SDNN 样本；空白不补零。日内超过 90 分钟、日/月缺失时不连线。ECG HRV 不混入健康 HRV 趋势。
- 健康查询只覆盖当前可见日、周、月或年，避免一次导入所有高频心率样本。今日摘要保存在受保护的本地 checkpoint；浏览其他日期时重新查询。读取失败明确保留错误，不把错误宣称为空白历史。
- 演示心率为显式合成值，与真实健康数据隔离；演示中不伪造 HealthKit SDNN。

## 列表与持久化

- 系统 `List` 复用历史行；简化波形预览，不为每行生成完整心电纸网格或玻璃表面。
- `RecordEntity` 新增日期+UUID索引、可选分析版本；分析 JSON 使用外部存储。页查询只解码元信息和小预览，不解码逐搏分析。
- 旧数据首次读取时补充轻量 `ECGListSummary`，完整分析在详情按需读取。SwiftData 仓库在后台创建并使用串行执行器，避免在主线程执行 JSON 和数据库工作。
- 同步每条分析后只替换对应的已加载摘要，不再每五条重载整个列表；结束刷新保留已加载页数。相同时间戳用 UUID 游标保持分页稳定。
- 日历选择直接查询当日 `[startOfDay, nextDay)`；支持左右切日、返回全部记录，无需逐页滚动找旧记录。日期边界由 Calendar 计算，涵盖夏令时。
- 卡片保留时间、心率、简洁预览和分类；删除固定导联/时长、Apple 分类徽标、百分比和节律分。只额外显示信号限制或分析状态；0.5.3起不再根据逐搏差异计数展示“心跳有变化”。来源、时长与节律依据仍在详情。

## 分段参考

- `x/y 次可测` 改为“基于 N 次清晰测量”；展开后显示未纳入数量与具体缺失原因。
- 本次最低–最高与临床教育参考明确区分。成人参考包括 P <120 ms、PR 120–200 ms、QRS <120 ms（明确其为常用增宽界限）、静息 RR 600–1000 ms。
- QTc 同时列男性约350–450 ms、女性约360–460 ms，不因不知道用户性别和年龄而给统一红绿判定。
- 偏离说明列生理、药物、传导变化及测量误差等可能原因，不作具体疾病诊断。单导联 ST/T、未校正 QT、TP 等无通用适用区间的项目明确说明，不虚构正常值。
- 参考资料：MSD [Electrocardiography](https://www.msdmanuals.com/professional/cardiovascular-disorders/cardiovascular-tests-and-procedures/electrocardiography)（本轮读取核对 QRS/QTc）；[LITFL PR interval](https://litfl.com/pr-interval-ecg-library/)（常用 PR 参考，当前环境抓取被网站拒绝）。阈值用于解释，不改变算法的测量接受窗口。

## 本次 ECG HRV

- 从当前完整分析动态计算，不把原始所有 RR 的标准差直接改名为正常搏动 HRV，也不写回 HealthKit。
- 仅来源分类为窦性、信号覆盖≥80%、有效时长≥20秒且没有明确的不规则节律、不稳定参考或来源限制时尝试计算；节律评分的心跳数量门槛不再单独阻止 HRV。
- 排除异常 RR、非有限数值、研究筛选范围外间隔、与质量缺口重叠的间隔，以及被标记/无法复核心跳两侧的间隔。
- 0.5.1 起合并本次记录中的合格间隔计算 SDNN 样本标准差，要求总计至少20秒、12个间隔和10对原本相邻的间隔。RMSSD 和聚集图严格检查原始 ID 与时间连续性，不跨被排除/缺失间隔连接，不插值。门槛是产品质量策略，不是临床有效性结论。这样30秒记录不会仅因中间一个干扰被切成两段而无结果，也不再要求慢心率必须产生20个间隔。
- Poincaré 图两轴同范围、绘图区等比例；点为连续相邻间隔。SD1/SD2 是差/和在45度坐标系上的样本标准差；虚线椭圆为一个标准差的分布，明确不表示正常区间或诊断聚类。
- 显示纳入秒数和间隔数；条件不足不显示计算数值，并给出原因。主界面提示比较相同时长、相似状态的记录。详细说明放在信息按钮中：短时没有通用正常区间，不能与5分钟、全天或 Apple 健康 SDNN直接比较。
- 参考：[An Overview of Heart Rate Variability Metrics and Norms](https://pmc.ncbi.nlm.nih.gov/articles/PMC5624990/)。筛选规则是研发策略，不是已验证的正常心搏分类器。
- PDF 同步加入本次 HRV 数值、筛选限制和分段参考文字。应用分析版本维持 `0.4.0-research`，因为已保存的信号/节律分析算法未改变；产品版本升级为0.5.1。

## 验证边界

纯 Swift 数值/边界测试、SwiftData 存储测试、模拟器界面验证分开记录。模拟器不能证明真实 Watch HealthKit 权限和采样接入、万条真实记录滚动帧率或临床准确性。实际结果见 `validation/heart-health-0.5/README.md`。

## 0.5.1 使用引导与界面

- List 内使用整卡 Button 加显式 navigationDestination，避免系统额外附加卡片外的右箭头。导航入口放在卡片右上角；纯概览不显示入口。折叠模块使用右上角加/减号。
- 记录提示改为“心跳有变化”，引导解释为间隔或形状与其他心跳不同，不等于疾病。
- 首次进入显示四步使用指南，关闭/完成后通过 AppStorage 记住；设置可重看。覆盖每日概览、趋势、日历、记录、波形、节律、分段/参考、HRV、备忘和分享。
- 设置移除技术性状态和存储实现说明，保留用户操作、隐私选择与清空确认。
- UI 测试使用 --skip-guide 避免干扰原有流程；指南专项用 --reset-guide 验证首次、完成持久性与设置重看。两个参数均不会改动健康数据。

## 0.5.3 首页提示规则

- 首页及每日详情共用的记录卡片，不再将研究性间隔/形态差异计数作为注意提示；详情分析保持完整。也不显示“无风险”或“安全”的结论。
- Apple 原始分类为心率偏高、心率偏低、房颤时，突出分类提示并加图标；高低心率同时强调数值。分类提示独立于分析进度和质量状态，不会被“等待分析”等状态覆盖。
- 信号不清晰使用中性状态文字。未增加新的 bpm 风险阈值，也不将每一个形态差异判定为危险或良性。
- 指南同步解释首页提示来源。显示逻辑仍只读取轻量元数据，不增加逐搏解码。
