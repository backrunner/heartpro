# HeartPro 开发决策

## 2026-09-17：第一版原生体验

- 按用户最新要求，使用原生 Liquid Glass：iOS 26+ 的 `glassEffect`、系统玻璃导航栏和浮动 tab bar；iOS 18–25 使用系统材质。避免给 ECG 波形增加透光干扰，内容纸张使用高对比实底。
- 视觉基线为珊瑚红、克制的青绿辅助色、26 pt 内容圆角、20 pt 页面边距、统一 SF Rounded 数字；深浅色跟随系统。支持字体缩放和 VoiceOver 标签，尚待完整可访问性审查。
- 保留 iOS 18 最低部署版本。当前构建及模拟器检查环境为 Xcode 27.0、Swift 6.4、iOS 27.0；iOS 18 回退路径尚未运行验证。
- 先使用一个 App target + 本地 `HeartProCore` Swift Package。领域模型、统计、研究性信号算法和合成夹具在纯 Swift 核心包内；HealthKit／SwiftData／UI 独立文件夹隔离。暂不把小规模代码拆成七个 package target。
- HealthKit 使用公开的 async query descriptor，避免手写多回调 continuation 状态机；没有申请尚未真机核实的 ECG 后台交付 entitlement。
- 最近 ECG 优先索引，然后按持久化 anchor 分批导入全部历史；分析任务以持久化 `pending` 状态在下次前台恢复。元信息列表采用 `(date, UUID string)` 游标；UUID 字符串显式使用 lexical 比较，排序与分页谓词一致。
- 默认模式没有合成记录。用户点「先体验示例」或开发启动参数 `--demo` 后进入独立内存演示，不混入真实 HealthKit。真实模式绝不输出演示参考分。
- 初版研究检测只提供质量、R 峰、RR 和统计离群点。波段边界、PR／QT、正常搏动 HRV、疾病或命名早搏分类、真实参考分继续关闭；没有数据验证就不提升能力名义。
- 本地备忘与健康症状写回分别报告。写回使用稳定 syncIdentifier 和版本，失败可重试；已写入的症状在初版编辑器中保持不可变，本地文字可继续修改。复杂的外部症状双向编辑／删除留待真机核实后实现，不伪装成已支持。
- 本地数据库、波形和临时导出采用系统完整文件保护并排除备份；不使用 CloudKit 或健康数据遥测。原始可再生波形缓存预算 256 MiB，结果和备忘独立保留。
- XCTest UI 流程在 `--uitesting` 下使用内存数据库并关闭 UIKit 动画，避免 iOS 27 的动画空闲监测影响测试；生产运行保持系统动画。测试显式使用 `-collect-test-diagnostics never`，避免本环境失败后诊断收集停滞，保留 xcresult、断言及截图证据。

以上实现决定不代表 P0 的真实 Watch 可行性验收或临床能力门槛已经通过。


## 2026-09-17：0.2.0 需求核对与界面修订

- 用户明确要求取消备忘主页面；备忘仅在所属 ECG 详情维护。主 tab 为心电和趋势，详情隐藏 tab bar。
- ECG 采用动态系统红，固定左侧电压轴；横纵缩放共享倍率，保留逻辑走速与增益。手动双点测量只显示时间／电压差。
- 移除口号、背景光晕和评分圆环；优先显示来源数据、覆盖情况和实测统计。玻璃用于导航与交互层，数据图表保留实底。
- 研究性分析版本升到 `0.2.0-research`，增加相邻 RR 散点、短—长组合、局部 R 振幅和模板偏离。所有结果明确是统计候选，不能升级为早搏诊断。
- 不确认正常搏动类型时，明确显示 RR 标准差与相邻差均方根，禁止标为 NN SDNN/RMSSD。系统 SDNN 继续独立展示；演示模式不会读取显示真实 HRV 缓存。
- 备忘持续时间是可选字段，兼容旧 JSON；选填后写回的独立症状 endDate 按持续时间计算。已写回症状的时间、程度、时长仍不可在本地修改。
- 旧分析版本重新排队，失败结果提供批量重试；导出文件在备忘变化后失效，重新生成时包含最新备忘和统计。
- [功能核对](./feature-audit.md)明确保留自动波段、已验证分类、NN HRV 与真实参考分的缺口；不能声称原始分析需求已经全部实现。


## 2026-09-17：0.3.0 逐段研究分析

- 根据逐段详细分析需求，将原先合并的占位说明替换为 P、PR 间期、PR 段、QRS、ST／J、T、QT、QTc、TP、RR／PP、U 的独立模块；U 波目前只说明不可测原因。
- 新增实际的全记录逐搏研究估计和合成数值／拒绝条件验证；只开放标明「研究估计」的描述值，不开放医学正常／异常判定。真实 Watch 同域验证仍未完成，不声称通过原规划中的临床或发布门槛。
- QRS 边界由局部斜率估计，P／T 使用振幅与安静区间；ST 使用轻度平滑的原始电压相对本搏 TP 候选基线，不使用 R 检测器高通数据。J+60／80 ms 与 T 波接近时拒绝采样。
- 指标分别统计可测搏数，不以整条记录质量比例代替分段覆盖；RR 不稳定、研究窗口外、低幅、缺口和不清晰边界保留具体原因。不存在的 Q／S 分量不填 0。
- QTc 逐搏配对 QT 和前一 RR，分别给出 Fridericia 和 Bazett；要求两侧邻近 RR 连续且差异不超过 10%，RR 范围为 500–1500 ms。此条件是算法支持窗口，不是正常范围。
- `segments` 为可选持久化字段；分析版本升级为 `0.3.0-research`，原有重分析队列处理旧结果，不改动原波形与备忘。


## 2026-09-17：分析文案易读性调整

- 分段说明先解释这段波形是什么、读哪些数字；公式、识别规则和算法条件收进「测量方法」。新增「这些数字怎么看」，解释毫秒、毫伏、中位数和分布范围。
- 页面使用「持续时间」「每次心跳」「未测得」等表达；保留中位数的统计含义，不将它改称平均值。P10–P90 在主界面显示为「中间 80% 范围」，明确它不是正常范围。
- 原有记录中保存的原因、形态和事件标识保持不变，显示时通过 AnalysisText 转为易读文案。旧记录立即使用新描述，不改数值、不升级分析版本，也不触发重新分析。
- 详情、单次心跳、波形对比、HRV 说明、设置和 PDF 同步用语。对不清晰波段解释原因，不把「没测到」说成「没有」或「正常」。


## 2026-09-17：分析模块布局与 Liquid Glass 修订

- 分段汇总收为一个有分隔线的玻璃列表，默认展示名称、中位数和测量覆盖；一次展开一段。分布、不可测原因和测量方法按需展开，逐次测量与原始波形仍完整保留。
- 「查看每次心跳」直接打开波形，默认进入首个有测量的心跳；通过前后按钮或选择菜单访问所有心跳，也能返回完整心电定位。
- HRV 默认只展示两个 RR 指标、散点图、一句来源限定及 Apple 健康 SDNN 趋势入口。计算含义、时长差异和未确认正常搏动的限制收进信息面板；不把 RR 统计改称已验证的 HRV。
- Liquid Glass 用于分析容器、信息按钮、指标菜单及逐次波形操作。原始波形与展开图表保留实底；降低透明度时容器使用不透明系统背景，iOS 18–25 回退为系统材质。
- Disclosure 和菜单使用明确的自适应 secondaryLabel 箭头色，标题与数值保持主文本色，不继承全局珊瑚红。详情、列表、同步状态、设置、备忘和校准信息用布局或自然语句代替中点分隔。
- 这次为展示层调整，未改变研究算法、持久化标识或分析版本。


## 2026-09-18：测量状态与六语支持

- 用「暂时无法测量」表示本次无法给出数值，并显示该项原因；U 波用「暂不支持」，尚无分析时用「等待分析」。汇总覆盖使用「可测」，与缺失状态对应。
- 简体中文、英语、日语、韩语、德语、西班牙语跟随系统 App 语言设置；设置中提供系统语言设置入口。未支持语言回退英语，中文变体使用简体中文。
- 采用原生 `.strings` 和共用 HeartProCore.L10n，使 SwiftUI、动态分析解释、Canvas 标签和 PDF 使用相同资源。翻译源文件与生成／检查脚本留在 Localization 和 Tools。
- 插值先构造可重排的占位符模板，再一次性替换参数；不会对用户文字中的花括号再求值。地区变体匹配相应基础语言，日期和小数按所选语言格式显示。
- 保持分析版本、持久化 enum 标识和算法原因不变，只翻译显示属性。应用已知错误保存稳定 messageKey，展示时翻译；系统提供的错误保留系统描述。用户备忘与真实 HealthKit 来源不翻译。
- PDF 长句按宽度换行，统计及事件使用实际内容分页，避免西文说明越过纸张边界。
- 单次心跳的开始／结束标签分别放在边界线外侧，避免较窄 QRS 在德语等语言下发生标注重叠。六语界面、PDF 与大字号验证见 [验证记录](./validation/localization-0.3/README.md)。

## 2026-09-18：隐藏尚未实现的项目

- 根据最新要求，U 波自动测量从分段列表、逐搏入口与 PDF 隐藏；以共享的 `ECGSegment.supportedCases` 控制显示。保留 U 的序列化标识及原有分析数据，不改算法版本、不触发重新分析。
- 真实健康评分缺少算法依据与验证，移除首页、每日概览、ECG 详情和趋势中的评分入口／占位，同时移除演示评分。概览统一展示记录数、心率与记录时长，记录卡片展示可分析比例。
- P、PR、QRS、ST、T、QT、QTc、TP、RR／PP 已有测量实现；本次记录无法给出值时继续展示具体原因，不把信号缺失误当作功能不支持。Apple 健康 SDNN 和 RR 描述统计保留。
- 设置与报告精简未开放功能的介绍，新增／调整的说明同步覆盖六种语言。历史规划中的评分与 U 波目标不代表当前产品入口。
- 核心 28 项、App 6 项及分段／趋势／六语 UI 定向回归通过，见 [本轮验证](./validation/supported-features-0.3/README.md)。

## 2026-09-18：0.4.0 继续研发早搏候选和评分

- 用户明确要求继续可研发能力，并强调早搏检测必要。本轮新增提前程度、前后 RR、局部 QRS 宽度与模板相关度联合判定；宽／窄／未定分类保持为候选，不宣称确认 PAC／PVC 起源。
- 节律参考分按 `round(100 × (1 − M/N))` 计算，一搏最多计一次；质量决定能否计算，不作为健康扣分。资格不足、推断配对节奏或 Apple 房颤／质量不佳时不出分。详情可查看分母、标记数、逐搏依据和原图，PDF 同步输出；不恢复固定演示分或评分趋势。
- U 波只在清楚的 T 结束与下一 P 开始之间寻找重复小波形。至少三次一致候选才显示模块；不强行缩短 T 波、不输出融合 U 的推测数值。
- 算法与 App 版本升级到 0.4.0；旧数据可解码，原队列重新分析。六语言资源同步，用户备忘与原始 ECG 不改写。
- 公开 MIT-BIH 八条记录对照已暴露复杂节律明显漏检，作为研发审计完整保留 TP／FP／FN 与拒答数量，不把较高候选精确率写成总体准确率。详见 [规则](./rhythm-analysis.md) 和 [验证记录](./validation/rhythm-0.4/README.md)。

## 2026-09-18：中文文案与信息层次

- 用户要求减少机械、难懂的描述。中文展示改用「疑似早搏」「节律评分」「标记的心跳」；分段介绍和缺失原因用短句，保留疑似性质、评分不代表健康、无法测量的具体原因。
- 早搏列表只展示时间、波形类别和提前了多少秒。分析次数、标记明细放在说明页，完整公式与阈值收进「详细规则」。原始依据和 PDF 仍完整保留；不更改检测或评分算法。
- `Localization/zh-Hans.json` 按目录 ID 保存中文展示文本。旧的查询键和已保存原因不改写，历史结果直接显示新文案，不需要重新分析。新 UI 字符串有完整六语翻译；其他语言的既有译文保持原样。
- 文案、模拟器界面与报告验证见 [本轮记录](./validation/copy-0.4/README.md)。

## 2026-09-18：报告排版与圆形信息按钮

- 根据用户要求，导出报告改为适合阅读和打印的白底排版：完整心电图在前，摘要、事件和分段测量使用表格，方法和备忘单独呈现。保持 25 mm/s、10 mm/mV 和完整记录时长。
- 报告使用专业、简洁的测量术语，宽／窄 QRS 仍标为疑似早搏；保留测量缺失原因、统计口径及评分限制，不新增诊断结论。新增用语同步六种语言。
- 信息按钮与逐搏前后切换统一为 44×44 pt 圆形玻璃控件，保留无障碍标签、降低透明度及旧系统回退。
- 未更改算法、版本、持久化标识或数据保护策略。最终 PDF、深浅色与大字号截图见[验证记录](./validation/report-design-0.4/README.md)。

## 2026-09-18：报告复用应用主题色

- 用户指出报告青绿色与应用不一致；报告改为直接复用 `HP.coral`，不再另设品牌色。浅红表头、分隔线和心电网格由同一色值派生，正文保持中性深灰。
- 4 项报告测试通过，实际 PDF 检查与产物见[主题修正记录](./validation/report-theme-0.4/README.md)。
