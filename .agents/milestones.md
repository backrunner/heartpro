# HeartPro 里程碑与验收

状态：目标里程碑基线。工程开发已开始，实际交付与检查记录见[实现状态](./implementation-status.md)。下文数值依然是预设验收目标，不能视为已经取得的成绩；真实 Watch／医学解释验证尚未完成。

## 1. 排期假设与依赖

建议配置：两名 iOS 工程师、一名信号处理／算法工程师，测试和设计持续参与，心电专业人员负责标注规则与解释审核。人员可以兼任，但不能取消独立测试与专业评审。

按完整依赖顺序，工程量级初估约 10–17 周；这不是发布承诺，不含受试者招募、同意流程、获取足够异常样本、伦理或产品用途审查的不确定等待。P0 结束后用真实设备与数据可得性重估。缺少同域验证数据时，先完成波形、历史、基础统计和备忘，高级能力保持关闭。

| 阶段 | 目标 | 预估 | 依赖 |
| --- | --- | --- | --- |
| P0 | 平台可行性、真实样本、术语与证据门槛 | 1 周 | 无 |
| P1 | Swift 工程、单条纵向链路、历史同步基础 | 1–2 周 | P0 |
| P2 | 波形、首页、日详情、趋势骨架与备忘 | 1–2 周 | P1；不依赖高级算法 |
| P3 | 质量、R／RR、基础统计、HRV与离群点 | 2–3 周 | P0 数据方案、P1 读取 |
| P4 | 参考分、日聚合、真实趋势、健康写回 | 1–2 周 | P2、P3 的已验证输出 |
| P5 | 波段与间隔、逐类异常候选、个人参照 | 3–5 周 | P3；独立标注和 Watch 数据就绪 |
| P6 | 全历史压力、隐私、可访问性、发布审查 | 1–2 周 | 所有拟开放能力达标 |

P2 UI 与 P3 数值处理可以由不同职责人员同期推进，但要先冻结领域模型。P6 的迁移、隐私和性能检查贯穿早期阶段，最后集中回归。外部数据不足不作为放宽验收阈值的理由。

## 2. P0：可行性与证据协议

**交付：** Xcode／Swift／iOS 版本决策、最小 HealthKit 探针、真实样本结构记录、症状映射表、ReferenceCatalog 草案、验证协议与数据许可清单。

任务：

- 固定 iOS 18+ 可行性与最旧目标设备；创建公开 API 的最小验证工程，避免先搭大架构才发现平台能力不符。
- 在有 ECG 的真实 iPhone 上读取样本元信息和完整电压，核对时间偏移、单位、真实采样率、导联、缺失字段及 Apple 分类。
- 验证近期和历史样本获取、原有关联症状读取、ECG 是否支持所需 observer／背景交付。记录注册失败和锁屏行为。
- 逐项确认六类候选症状写入类型、合法值、编辑替换、删除与 syncIdentifier／syncVersion 行为；只在开发者明确选择的测试数据上测试写入。
- 核定背景任务与数据保护的取舍；核查文件备份排除和 SwiftData CloudKit 关闭方法。
- 固定 R 峰匹配容差、事件标注定义、P／QRS／T 边界规则、拒答统计方式和数据拆分方案。
- 精读并核定参考区间，补核当前未成功读取的 MIT-BIH 资料及各数据集许可；不将许可未知数据直接放入仓库或 App。
- 确认产品术语采用「心电记录参考分」，以及心梗／缺血不作为筛查能力；形成 `decisions.md` 和能力矩阵。

**退出条件：** 能展示至少一条完整真实波形并和 Health App 同一记录核对；已记录全部不可承诺项；所有拟用 API 的可用性有编译／真机证据。无 ECG 真机或合法数据时，后续只能以模拟数据推进 UI 和工程，不能宣称 HealthKit 或算法验收通过。

## 3. P1：工程与数据闭环

**演示：** 授权 → 读取一条真实 ECG → 保存元信息与波形 → 显示基础来源字段 → 重启仍可读取 → 增量刷新。

**交付：** Swift target 划分、HealthKitGateway、Repository、原始文件格式、SyncCoordinator、任务队列、基本路由、只含合成／获许可数据的夹具工具。

验收：

- 严格并发检查下编译；HK 对象不被任意跨 actor 传递；查询完成／错误／取消只完成一次。
- 全量与 recent 查询重复到达时 UUID 唯一、条目数稳定；相同时间不同 UUID 不漏记录。
- 人为在批次提交前／后杀进程，恢复后 anchor 不跳过未持久化记录，任务不永久卡在 running。
- 删除样本后隐藏来源记录、使结果失效并清理文件；晚到计算不能复活已删记录；本地备忘按策略保留。
- 查询为空不宣称读取权限被拒；部分授权、无数据、无配对 Watch、尚未同步均有准确状态。
- 波形完整性失败有独立原因；不以缩略图代替原始数据。
- 迁移框架及基础备份排除验证到数据库、旁路文件和原始波形目录。

## 4. P2：页面、纸质波形与本地备忘

**演示：** 首页无限下滚 → 点击当日卡 → 左右切日期／跳转日历 → 切换趋势 tab → 打开 ECG → 横向查看全长 → 新建并编辑备忘 → 返回原位置。

**交付：** Timeline、DailyInsights、ECGDetail、Canvas 波形、详情总览、分析模块占位状态、本地备忘、PDF 初版。

验收：

- 卡片顺序满足「波形 → 结论 → 分数／bpm／基础信息」；当天卡与全历史列表同时存在。
- ECG 详情中总览在所有分析模块之前；未知指标明确不可测；任何演示数据在开发构建显著标识，生产数据绝不使用假结果占位。
- 25 mm/s、10 mm/mV 的坐标公式、1 mV／200 ms 校准标记和单位换算通过固定夹具核对；屏幕不声称物理毫米准确。
- 采样缺口断线；缩略图标真实时间；LOD 不丢窄尖峰；缩放、横屏与全长末尾可达。
- PDF 使用物理尺寸、可打印页宽与连续时间条带，不能裁掉末尾；人工按 100% 比例打印或量测 PDF 坐标核对。
- 分页 10,000 条合成元信息不反复重载、不掉行；滚动返回位置稳定。
- VoiceOver 可从波形摘要进入事件列表；所有手势有按钮替代；Dynamic Type 不遮挡关键单位与免责声明。
- 备忘多条、快捷标签互斥／组合、时间与程度编辑、重启保存、原 ECG 删除后保留行为正确。

此阶段不把图表占位和可点击页面称为已完成算法分析。

## 5. P3：基础信号分析

**演示：** 完整波形与质量条、R 标记、RR 图、bpm 分布、合格 NN 的 HRV、全段离群候选，点击候选定位到原始波形。

**交付：** 确定性 Swift 管线、信号支路、分窗质量、R 峰／RR、统计公式、HRV 门控、离群点模块、固定解释模板、可复现的基准报告。

### 5.1 算法测试协议

- 使用合成信号验证采样率、单位、缺口、倒置 QRS、噪声、饱和、平线、不同心率和已知心搏位置；公式结果和异常路径均有断言。
- 公开数据库用于方法验证；LUDB 的 I 导联、QT Database 已标注片段与其他导联分别报表，不混为 Watch 成绩。
- 按受试者分训练／调参／最终测试，不能按心搏随机分割；同一受试者、同一记录切片及数据库间重叠记录不得跨拆分。
- 最终测试集冻结后不反复调阈值。数据版本、hash、标注版本、配置和 benchmark 命令写入报告。
- 指标同时报告 accepted 子集准确度、总样本覆盖／拒答率、信号质量分层和失败例；不能通过大量拒答获得虚高准确度。
- R 峰一对一匹配，初始容差 ±50 ms；另报精定位时间误差，避免宽容差掩盖 HRV 所需的时序精度。

### 5.2 初始量化门槛

以下为开发目标，P0 预注册后不得根据最终测试结果临时下调：

| 能力 | 初始目标 | 失败策略 |
| --- | --- | --- |
| R 峰 | 合格片段敏感度与 PPV 各 ≥99%；同时报告受试者聚类置信区间 | 不开放依赖它的评分／HRV |
| R 精定位 | 合格数据绝对时间误差中位数 ≤10 ms、P95 ≤25 ms | 改进定位或收窄适用质量范围并重验 |
| 平均 bpm | 与人工确认可靠 RR 所得值 MAE ≤2 bpm | 分来源展示，停止本地摘要发布 |
| HRV 数值公式 | 固定 NN 夹具与双精度基准一致，误差 ≤max(0.001 ms, 基准值的 0.01%) | 修复数值实现 |
| HRV 端到端 | 与同一合格时间段人工 NN 结果比较；初始误差目标 ≤max(5 ms, 10%)，逐指标报告 | 保留 RR 图，抑制 HRV |
| 质量门控 | 不能将真实异常一概当噪声；覆盖／误拒／误接收分开报表 | 调整质量模型并重验 |
| 离群候选 | 零 MAD、小样本、重复事件合并、噪声区排除和定位全部正确 | 关闭自动解释，只展示分布 |

数值公式通过不代表真实记录 HRV 准确。任何置信区间过宽、重要子组缺失或总覆盖过低都不能只凭平均值过线。

**退出条件：** 各基础模块有明确支持范围和拒答原因；同一记录重跑稳定；有 Watch 同域试点证据，或明确保持内部实验、不得宣称产品验证完成。

## 6. P4：参考分、日聚合、趋势与症状写回

**演示：** 同一日多条真实已完成记录形成透明聚合；点趋势可回到组成记录；备忘保存后可以独立查看健康写回状态。

**交付：** ScorePolicy、DailyAggregator、TrendService、版本重算、健康症状 outbox、权限文案、数据管理页。

验收：

- 分数 N、M、规则集合与波形心搏能对应；同一搏动不重复扣分；没有资格时输出 nil。
- 加入伪差不能简单制造低分；HRV 高不直接加分；高分不覆盖 Apple 分类、波段越界或症状提示。
- 评分初始策略通过稳定性与可理解性评估：同一信号轻微无关扰动不造成大跳变；用户能理解它不是疾病概率。没有足够证据则公开开关维持关闭。
- 当日分数和年趋势按模块设计公式复算一致；极端记录的候选提示不会被中位数隐藏；每个指标分母可查。
- 测试无记录、单记录、部分分析、不同算法版本、跨午夜、时区切换、夏令时 23／25 小时日、周起始设置及闰年。
- HRV 两种来源分开、不同片段时长分层；没有把缺失值填零或跨断点拼连续曲线。
- 写回测试覆盖初次授权、拒绝写入、部分成功、保存后杀进程、编辑、重复重试、删除、健康 App 外部删除；不得改动 Apple ECG。
- 自由文本和不支持标签只留本地；不把检测到的候选事件自动写成症状。

**退出条件：** 可成为内部完整体验版本。是否可以对外显示参考分独立判定；不因为趋势 UI 需要数值而降低评分门槛。

## 7. P5：波段、间隔与进阶候选

**演示：** 总览列出各波段统计／范围／有效样本数；代表性心搏、逐搏间隔分布与候选事件均可定位；不可测 P／T 有明确原因。

**交付：** 分波段模块、ReferenceCatalog 正式版本、按类别开启的候选检测、个人变化参照、专家复核报告。ST／T 研究若无独立证据继续关闭，仅保留限制说明。

| 能力 | 初始验收目标 | 补充条件 |
| --- | --- | --- |
| QRS 边界／时限 | 合格测量绝对误差中位数 ≤15 ms、P95 ≤40 ms | 对匹配标注分别报告起点、终点与时限；至少报告两位标注者分歧 |
| P／T 边界 | 合格测量绝对误差中位数 ≤25 ms、P95 ≤60 ms | 逐边界与波形类型报表；端点误差过大时抑制派生 PR／QT |
| 命名早搏候选 | 每个拟开放类别敏感度与 PPV 各 ≥90%，95% 聚类置信区间下界初始目标 ≥85% | 不能用全部事件平均掩盖某一类失败；检测和类型分类分别评估 |
| 负样本误提示 | 初始目标 ≤0.05 个误事件／30 秒，另报有误提示的记录比例 | 在有现实噪声、体位变化和不同心率的 Watch 记录上测量 |
| 个人变化参照 | 无未来数据泄漏、无当前记录自参与、分层与最低样本约束正确 | 不把偏离历史解释为疾病，也不把历史稳定解释为健康 |

这些是参考性功能的工程研究目标，不构成诊断产品的充分验证标准。目标必须结合标注者一致性、误差传播、可接受覆盖率和实际用途审核；达不到就不开放。

**数据充足性：** Watch 试点可从不少于 50 名参与者、200 条经同意的记录启动，用于发现域差异；这不是发布样本量。正式独立验证按预期患病／候选事件比例和置信区间宽度做样本量估算，保证各开放类别、设备／系统、质量、年龄段和心率范围有足够独立受试者。若无法取得某类阳性样本，该类别标为“未验证”，不可依据公共数据库单独放行。

**退出条件：** 每项能力标记 `validated / experimental-off / unsupported`，给出理由；用户界面与商店描述只包含已验证能力，不宣传“识别所有异常搏动”。

## 8. P6：可靠性、数据保护与发布

**交付：** 全流程回归记录、Instruments 报告、数据删除验证、可访问性审查、隐私说明、方法说明、发布能力清单和已知限制。

### 8.1 必测矩阵

| 维度 | 最少覆盖 |
| --- | --- |
| 设备／系统 | 最低支持 iPhone 与较新 iPhone；真实 HealthKit；目标系统的最低和当前版本 |
| 历史规模 | 0、1、30、1,000、10,000 条索引；不同天数分布与相同时间戳 |
| 数据情况 | 完整／缺口／短记录／未知采样率／倒置／低质量／异常候选／字段缺失 |
| 生命周期 | 冷启动、前后台、锁屏解锁、系统取消、强杀、重装或本地清空后重索引 |
| 资源 | 低电量、热限制、磁盘不足、文件损坏、缓存逐出、后台预算不足 |
| 删除与权限 | 明确的来源删除、读取返回空、写入撤权、本地清理与自有症状删除失败 |
| 时间 | 跨日、夏令时、时区变化、闰年、无记录日期、系统时间／日历设置变化 |
| UI | 长列表、手势冲突、横屏、返回定位、VoiceOver、大字号、深浅色、减少动态效果 |

合成一万条测试用于压力，不宣称已经完成一万条真实 HealthKit 样本的导入验证。后台交付只报告实测条件下的表现，不保证实时或后台无限运行。

### 8.2 发布阻断项

- 存在已知漏读／重复、删除后复活、备忘丢失、源数据被意外修改、撤权状态误导。
- 能从正常日志、崩溃报告、默认云备份或后台快照获得个人心电／症状／备忘。
- 参考分、HRV或命名候选没有达到各自证据门槛却仍在公开构建启用。
- 页面或商店描述声称能识别／排除心梗、心肌缺血或替代诊断，或者使用高分暗示无须就医。
- 参考区间无依据、版本混合导致虚假趋势、不可测项被呈现为正常。
- 无法提供拟发布能力的方法说明、测试集独立性及已知限制。

发布前审核 App Store 1.4.1、5.1.3 与目标市场用途要求。这里的发布门槛是产品证据要求，不是让实施每个可逆工程任务都等待额外审批。
