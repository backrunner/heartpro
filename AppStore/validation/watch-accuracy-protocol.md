## 冻结版本与预先定义标准

记录 app 版本、构建号、源文件 SHA-256、ECGAnalysis.currentVersion、节律 policyVersion、设备/系统、排除规则和算法参数。在接触独立测试集前，由有资质的心电专家明确目标用途、每项指标的接受标准、样本量依据和统计计划。不能测试完再调阈值以“通过”。Apple 不为本 app 提供统一的临床通过阈值。

## 数据与参考真值

- 必须有合法授权、去标识化的真实 Apple Watch 单导联电压数据及原始采样率，覆盖实际部署的硬件、系统、心率、信号质量和节律。
- 不从用户设备静默导出健康数据，不上传到网站或支持邮箱；本次不访问个人 Health 数据。合成示例和 MIT-BIH Holter 数据仅用于研发回归。
- 以参与者划分开发/验证/独立测试，避免同一个人的波形泄漏到不同集合；记录纳入、排除和不可评估记录。代表性不足要明确说明。
- 两名独立有资质的标注者在不知道算法输出的情况下标注峰位、波段边界及候选类型，分歧由第三方或预定共识流程裁决。记录观察者间一致性。
- 如组织涉及人体的健康研究，先核对知情同意、伦理审查、退出流程及 Review 5.1.3(iii)/(iv)；不能把“算法测试”作为绕过依据。

## 必须覆盖的结果

| 能力 | 证据要求 |
| --- | --- |
| 原始波形/手动两点 | 对原电压/时间采样核对单位、倒置、缩放、滚动、完整时长及导出比例；覆盖 256/512 Hz 等真实采样 |
| R 峰/心率/RR | 匹配容差须预定义；报告漏检、误检、灵敏度、PPV、时间误差及每人/每条分布 |
| P/PR/QRS/ST/J/T/QT/QTc/TP/PP/U | 逐指标报告可评估覆盖率、缺失原因、平均偏差、绝对误差、误差分位数及 Bland–Altman 一致性界限；不能只报成功输出子集平均误差 |
| 早搏候选/宽窄规则 | 逐类 TP/FP/FN、灵敏度、PPV/F1、置信区间；按节律、信号质量、心率分层；不把宽窄等同起源 |
| 节律参考分 | 验证分子/分母及剔除规则；评估漏检时的高分风险；不得解释为心脏健康分或风险概率 |
| ECG HRV | 用标注的间隔验证 SDNN/RMSSD、成对间隔不跨缺口、可用时长与覆盖；单独评估短时估算；不宣称等同标准五分钟 HRV |
| 信号质量/拒绝输出 | 评估平线、运动、漂移、倒置、低振幅、间断、边缘波段、房颤和复杂节律；统计拒绝率与不安全输出 |
| 引用/临床描述 | 参考区间、就医文字、因果解释与实际证据一致，医学专家及各目标语种审校 |

用参与者层级 bootstrap 或适当方法计算区间，避免把同一记录大量心搏当成独立人群扩大置信。保留失败记录，不将缺失补零。不用 Apple 原始分类充当波段/早搏真值。

## 交付

1. 数据来源、授权、参与者分组清单（去标识化 ID）、硬件与采样分布。
2. 冻结参数、预定义接受标准、盲法标注与裁决说明。
3. 各项误差、覆盖、混淆矩阵、置信区间和失败案例；独立审阅人结论。
4. 用相同冻结版本复跑的软件/真机验证；变更算法后重新评估受影响能力。
5. 对外方法页面和 App Review 附件，只陈述有证据支持的范围，不将测试完成自动视为获批。

模板见 `watch-records.csv` 和 `validation-summary.json`。当前没有合法授权的独立 Watch 数据/专家标注，无法在本次开发会话内完成准确度认证。
